## Why 0.9.0

A seventh Scene is now refused instead of dropping the oldest one, Scene tiles for a missing screen show a new place and size, and the Preferences save and the toolchain changed. That is new behaviour without a breaking change, so a minor version, as for 0.8.0. The Preferences schema stays 15.

## What ships since 0.8.0

- Preferences are saved in one step with a last good copy (ADR 0039, PR #60): a save writes its own temporary file and renames it over `preferences.json`; a cut-off `preferences.json` opens with `preferences.last-good.json` and is repaired on the next save. Two copies of CamFrame running at once can still save over each other's whole document (no single-instance lock).
- Electron 44.11.3, Vite 8.3.8 and Electron Builder 26.18.1, with audit fixes for undici, source-map-js and fast-uri (PR #61): `npm audit` went from 4 high to 0 high (6 moderate left, `minimatch` under Electron Builder's macOS universal-build path).
- One Scene session module owns live Preferences, the Active Scene and Undo (PR #62); nothing visible.
- After a toolbar Shape or size change the Active Scene keeps the place the window really lands on (B1, PR #63; before, applying the Scene again could put the camera 63 px off).
- One layout-request module for Scene tiles and apply (B2, PR #64): a tile for a Scene saved on a screen that is gone now shows where the Scene really opens, at its shrunk size, and tiles are sent again after a move starts, a display changes or the window heals itself.
- One Scene library answers a Scene's kind, look, size and place (PR #65); nothing visible.
- The Scenes tab's state lives in its own tested module (PR #66); nothing visible.
- A seventh Scene is refused everywhere and the six saved Scenes stay as they were; screen readers hear "Not saved: CamFrame keeps 6 Scenes. Delete one to save a new one." (B3, PR #67).
- The Prompter link stays open on purpose as a public interface on this computer (ADR 0040, PR #68); behaviour unchanged, documentation only.
- The 0.8.0 post-tag record (PR #59); nothing in the app.

## Rollback to 0.8.0

v0.8.0 stays published. A Preferences file written through this branch's `src/preferences-store.js` (six layout Scenes, list view, a small size of 300, saved twice so the last good copy exists) was loaded through v0.8.0's `preferencesFromDocument` and through this branch's (a scratch script, not checked in):

- Kept: both loads give the same settings, and a document saved back from 0.8.0's load loads the same in 0.9.0 again. The only change to `src/settings.js` since 0.8.0 moved the list of look keys into the Scene library (`src/scenes.js`); how a document is read and written did not change, and the schema stays 15.
- Lost or changed: 0.8.0 reads only `preferences.json`; `preferences.last-good.json` stays on disk unused, and 0.8.0 saves by writing the file directly again. This release's fixes are gone: a seventh Scene drops the oldest one again, the Compact place and Scene tile fixes and the Electron bump are lost.
