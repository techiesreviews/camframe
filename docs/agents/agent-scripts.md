# Agent Kit (CamFrame)

Agent Kit is required for all coding in this repo, for every model and provider, including delegated workers. CamFrame uses the shared, machine-wide kit (`~/.local/share/agent-kit/current`, set up with `kit init --light` on 2026-10-30); the repo holds only its launcher (`scripts/agents/kit`), hook launcher (`scripts/agents/hooks/run.sh`), settings (`scripts/agents/kit.json`), one project command (`scripts/agents/project.d/shots`) and `.gitattributes` (`* text=auto eol=lf` from `kit init`: LF line endings in every new checkout; an existing one keeps CRLF in a file until it is checked out again). The kit itself is never copied in.

Work in a git worktree, not the main checkout. Run `scripts/agents/kit --help`, each relevant command's `--help`, and `scripts/agents/kit doctor` before implementing. Every command ends with one `RESULT: ok|fail …` line.

| Command | What it does here | Evidence |
| --- | --- | --- |
| `kit doctor` | Worktree place and base, hook config, Node, conflict markers, every command's `--help`, the kit copy. | stdout |
| `kit unit [files…]` / `kit unit --affected` | `node --test` over `test/**/*.test.js` (the same suites as `npm test`), or only the files a change touches. | `.scratch/unit/*.log` |
| `kit shots` | Project command. Serves `src/` on a free `127.0.0.1` port, opens `overlay.html` in Chromium without Electron (the browser QA fake), opens Inline settings → Scenes and captures the Prompter link off, on, and with a busy port (`?prompter=busy`) at the default Overlay size (324x390) and a tall view (plus the Camera tab's switches and the link in high contrast), then the toolbar's Prompter link button off, on (from the keyboard) and busy, checking that the button and the settings switch agree both ways and that all six toolbar buttons fit the default Overlay at full size, and that a Corner margin update leaves the focused Face full choices in place (not rebuilt). Fails on page errors or missing controls. Playwright comes from `KIT_PLAYWRIGHT_MODULE`, else `playwright` in `kit.json`: the repo's own `playwright-core` devDependency (`node_modules/playwright-core/index.mjs`, so run `npm ci` first; its Chromium comes from `npx playwright-core install chromium` when it is not already cached). | `.scratch/shots/<time>/` |
| `kit review` | Read-only review of a commit or range, with the kit's pinned reviewer. | `.scratch/reviews/` |

`kit.json` holds no machine paths: there is no `mainRoot` (the kit then uses the main worktree git reports, or `KIT_MAIN_ROOT`), and `playwright` is relative to the repo.

Branches (`branches` in `kit.json`): work lands on `dev` through `scripts/agents/kit pr` (with the lead's authorisation, below), and `main` is the release branch, released from `dev` with `scripts/agents/kit pr --release --base main` (kitchen tickets 89 and 90 in the Native Site Editor's `docs/wayfinder/kitchen-everywhere/`). What enforces this: the kit's command guard refuses an agent's raw `git push` to `main`, and `kit pr --release` only cuts a release from exactly `origin/dev`, unless a lead waives that check with `--waive "<reason>"` (the result line records the waiver). Neither stops a person pushing from their own terminal or a GitHub pull request into `main` from another branch; there is no GitHub branch protection on `main`. Releases (the `v*` tags the desktop build runs on) should be tagged on `main`; nothing checks which branch a tag is on (`.github/workflows/build-desktop.yml` builds any `v*` tag).

The launcher `scripts/agents/kit` is the shared kit's own `launcher/kit`, copied unchanged by `kit init` (the same file every shared-kit project carries). It runs the machine copy, which `kit update` keeps at the shared kit's `main`; only where there is no machine copy (CI, a cloud session, a new laptop) does it shallow-clone `main` of `KIT_REPO`. It is deliberately not pinned here: the shared kit's rule is that every project runs the newest kit, and a kit change lands only after its own CI and the Native Site Editor's tests pass against it. Pinning only this repo's fallback would make CI run a different kit from every desktop. The rule and the launcher are the shared kit's (its `README.md`, "How a project uses it" and "Changing the kit"), so the decision is recorded there, not in a CamFrame ADR. To try or fix a kit version, set `KIT_HOME` to that kit's folder. Do not edit the launcher here; change it in the shared kit.

The real-Electron smoke test (`npm run test:electron`, `scripts/electron-smoke.mjs`) needs `node_modules` (Electron and `playwright-core`, from `npm ci`) and a display; it is not wrapped by the kit. Its Prompter link test uses the real port `47833` and fails at once when that port is busy (quit a running CamFrame first). `.scratch/` is git-ignored. Do not use `kit pr`, `kit slice` or other publishing commands unless the lead authorises it.
